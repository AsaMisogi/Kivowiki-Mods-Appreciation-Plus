# 工程说明与验证记录

## 范围与接入

所有新增内容位于 `My-Mods/Kivowiki-Mods-Appreciation-Plus`。没有修改 Core、后台管理器、其他模块或 API 文档。模块通过清单 v4 的 page 模式表达式入口导入；依赖与权限只使用 Core 文档公开的 API。

页面适配于 2026-10-05 核对角色 3 与 365 的生产页面。只读取角色路由、鉴赏标题及 `.n-tabs-tab--active[data-name]`，不依赖 Vue 私有实例、页面全局变量或打包后变量名。入口放在对应标题旁。关闭窗口、切换路由和停用模块都会清理模块自身节点，原生播放器及导出入口始终保留。

两页当前播放器的骨骼版本为 Spine 4.2；参考样本为 4.2.33，采用匹配的 4.2 Runtime。模型为 GLB，独立光环为 OBJ。当前适配支持 Spine 4.2、GLB/GLTF 与 OBJ；没有声称兼容未经验证的其他骨骼主版本。

## 渲染与交互

Spine 使用原始骨骼与原始图集，并启用抗锯齿、线性采样与 mipmap。显示尺寸、设备像素比、超采样倍率和骨骼变换分别处理，滚轮缩放锚定光标位置。默认保留原站的 Additive → Screen 修正与 `_R` 辅助轨道；可在设置中关闭加色修正。

3D 模型按原站约定转换 toon 材质：身体是不透明表面，只有眉毛保留原透明标记和顶点色。嘴部按空间连通性分离，保留蒙皮骨骼、UV 和权重；贴片保留深度测试、关闭深度写入并使用负 polygonOffset，防止与面部共面闪烁。相机 near/far 随观察距离调整，避免原先 1e8 深度范围比损失精度。嘴型图集使用 8×8 分格、repeat=0.5、flipY=false；先扣除模型原始嘴部所在的 4×4 分区原点，再定位目标图格。四套图集随包提供。

窗口使用原生 dialog 的焦点约束和背景不可交互语义；Esc 关闭、按钮有明确中文名称、控制面板可以滚动，小屏改为上下布局。全屏调用发生在用户点击事件内，请求目标为外层 div，不能使用 dialog；进入后重新置顶 modal。被浏览器拒绝时保留网页浮层。关闭后恢复入口焦点与 body 原有 overflow。

## 导出与生命周期

1. 图片裁剪保存为 `[0,1]` 归一化矩形，在目标画布尺寸上转为整数像素。先以目标尺寸真实渲染，再裁剪；PNG 保留 alpha，JPG 铺白底。
2. 批量以选中的动画为单位，在同一取帧时间、构图和选区上依次处理，PNG/JPEG 以不重复压缩的 ZIP 交付。
3. 视频按固定时间步逐帧生成 JPEG 中间帧，在 Worker 内由 FFmpeg 编码。不是 MediaRecorder 实时录屏，不会因为预览掉帧而少帧，也不把 MP4 改名为 MOV。
4. MOV/MP4/MKV 使用 H.264。测试发现当前单线程 WASM 的 VP9 路径发生内存越界，因此 WebM 明确采用通过实际验证的 VP8；没有隐藏失败或静默换后缀。
5. 转码 Worker 按任务创建，结束、失败、取消或关闭时直接终止，释放整个 WASM 堆。传输帧使用 transferable ArrayBuffer；中间文件总量上限 256 MB。
6. 预览和导出都受显卡纹理尺寸及 1600 万像素画布预算约束。预览自动限幅，导出不能满足精度时返回具体提示；不会把低分辨率截图偷偷放大。
7. 导出期间禁用会改变构图的控件，保留关闭和取消。结束或取消后在 finally 中恢复动画和预览尺寸。
8. Pixi 资源采用串行操作与引用计数，防止快速关闭/重开时迟到的资源卸载影响新窗口。Three.js 显式释放 geometry、material、texture、controls 与 WebGL context。
9. 上一次下载 Blob 在下一次导出或关闭时释放；DOM 监听器、观察器、定时器、RAF 和临时 Object URL 均有对应清理。

### 扩展资源消息兼容

核对 Core 1.6.3 的 `module-store.js`、`background.js` 与 `content.js` 后发现：`getFile` 的 Blob 会直接经过 `chrome.runtime.sendMessage` 返回。Chrome 的 JSON 消息序列化不能可靠保留 Blob。因此本模块不使用 `getFile` 传二进制，也不修改 Core：构建时把 WASM 和嘴型图集转换为每块最多 2 MiB 原始数据的 base64 文本，运行时只调用公开 `assets.getText`，按顺序还原到 Uint8Array。Worker 脚本本来就是文本，同样使用 `getText`。所有文本分块均包含在发布包中，单条消息约 2.7 MiB；读取过程中检查取消，完成后把 WASM buffer 转移给 Worker。

发布包测试逐字节比对还原的 WASM 与锁定依赖原文件。浏览器测试刻意让 `getFile` 返回空对象，并仅提供可用的文本资源接口，以覆盖这一兼容条件。

## 1.2.0 嘴型与播放控制

### 嘴型定位校对

角色 3 的模型 218（Azusa）嘴部 UV：U=0.008647–0.241360，V=0.792588–0.957420；角色 365 的模型 327（CH0242）：U=0.008695–0.239629，V=0.792338–0.956216。它们都在原贴图的 U=0–0.25、V=0.75–1 分区。旧代码只缩放 UV 并加目标格偏移，未减来源原点，使 V 多出 0.375，即通用图集的三行，末几行还回绕。

现在从分离后的嘴部网格 UV 计算来源分区原点，采样公式是 UV × 0.5 + 目标格原点 − 来源分区原点 × 0.5。缩略图仍从左上按行编号 1–64。没有按模型名字写死偏移，也没有把 UV 包围盒拉满一格，因此原有嘴型宽高比例、蒙皮权重和透明边缘保持。单元测试用实际 GLB 的 UV 边界经 Three.Texture.transformUv 校验全部 64 格。

### 时间控制与原有效果

- 独立 fieldset 将播放控制放在画布下方；导出和加载期间与侧栏一起禁用。原生 range 支持鼠标、触屏与键盘，读屏可获取当前秒数与总时长。拖动后暂停并同步图片取帧时间。倍速为窗口内预览设置，不改变原动画时长、导出 fps 或视频播放速度。
- 预览仍由同一个 RAF 驱动，拖动事件合并到每帧，释放和键盘操作立即应用。切动画取消待处理定位，归零并保留播放状态；关闭窗口由现有 Scope 清理。无动画的模型与零时长 Spine 姿态保留静态显示、图片导出和可用的动画切换。
- Three 在 seek 时使用 LoopOnce + clampWhenFinished，保证精确末帧可见；播放恢复 LoopRepeat，并解除 paused。
- Spine 从 setup pose 重置，保留皮肤及常驻辅助轨道；无物理约束时直接采样轨道时间，有物理约束时用 1/60 秒小步重演。倒退不会继承旧姿态的物理惯性，较长物理动画定位开销与目标秒数成正比。
- 等于动画时长时保留末帧；超过时长的图片采样继续采用原有循环语义。导出结束 / 取消恢复之前的动画与时间，播放状态、倍速和相机视角由窗口保留。

### 中文命名

词典只解释已观察到的动作段，模型资源前缀在识别到动作词时省略；数字差分、阶段、序号和变体均保留。A / M 没有未经确认地扩写成具体含义。未知词保留，完全未知的动作标为“未分类”；中文同名追加顺序号。仅改变 option.textContent，option.value、导出命名、主动画过滤和播放顺序不变。单选下方显示当前原名，批量列表下方显示全部选中原名。

## Git 仓库分发

仓库根目录保留 `module.json`，并提交 `dist/index.js`、`dist/config.js` 和运行所需的 `assets/`、许可证。Git 市场不会替使用者执行 npm 构建，因此不能只提交源码。源码、测试、构建脚本和锁文件也保留，便于独立克隆后维护；`node_modules/`、`.research/`、`test-results/`、`release/` 不进入 Git。

市场发现使用 GitHub 的 `kivowiki-mods` Topic，再读取默认分支根清单和入口。本仓库保持私有时无法被公开市场读取；改为公开后，Topic 索引更新时间由 GitHub 决定。尚未被索引时可以直接粘贴仓库 URL 导入。设置 Topic 不代表官方审核或认证。

新增的市场集成检查调用 Core 的真实 `discoverGitHubPackages`，只将 HTTP 边界替换为本地已提交文件，用于验证清单、兼容范围、主入口和配置入口。它不宣称验证了尚未公开的仓库在在线市场中的搜索排名或可见性。`npm run check` 当前共 15 项测试；Core 源码位置支持 `KIVOWIKI_CORE_DIR`，独立克隆未提供 Core 时会明确跳过两项 Core 集成检查。

## 1.2.1 回忆大厅填充构图修复

### 原因与取景约定

1.1.0–1.2.0 先取主背景附件边界，再寻找最大不透明矩形并居中裁切。这个方法保证覆盖率，却把背景纹理的中心当作镜头中心；不对称背景、羽化边缘和画外内容会改变人物在最终画面里的位置与大小。

核对项目内保存的站点播放器实现：`calculateHomeParameters("fill")` 使用 `scale = width / 3000`、`height = width * 9 / 16`；填充时 `initSpineRender` 将骨骼放在画布 `(width / 2, height)`，不调用包围盒定位。将这一变换还原到 Pixi 的 Y 向下坐标，取景为 `{ x: -1500, y: -1687.5, width: 3000, height: 1687.5 }`。

`src/util.js` 的 `homeFrame` 统一提供这一构图，预览与图片、视频导出共用。没有添加角色专属偏移，也不随动画逐帧调整镜头。完整显示仍使用主背景边界，无主背景时回退骨骼声明边界；立绘裁剪与模型视角不受影响。移除旧 alpha 扫描及其单调栈算法，避免为取景额外渲染和读回 GPU。

填充优先保持站内构图，不能以移动镜头来消除其他资源本身的透明边缘。原有预览平移和缩放仍用于观察；回忆大厅保存仍按所选取景输出，不将临时预览操作写入固定镜头。
